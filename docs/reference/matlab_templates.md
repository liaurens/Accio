# MATLAB Template Reference

This document explains all MATLAB templates generated by the Tool Wizard. These templates follow the **USAIN pattern** used for MATLAB tool development.

---

## Quick Reference

| Template | Output File | Required | Purpose |
|----------|-------------|----------|---------|
| tool_main.m | `MyTool/MyTool.m` | Yes | Main class entry point |
| contents.m | `MyTool/Contents.m` | Yes | MATLAB help documentation |
| datakeys.m | `MyTool/+mytool/DataKeys.m` | No | Constants for data passing |
| schema.m | `MyTool/+mytool/+inputs/get_schema.m` | No | Input validation schema |
| step_load.m | `MyTool/+mytool/+io/LoadExternalFilesStep.m` | No | Load external files |
| step_write.m | `MyTool/+mytool/+io/WriteFilesStep.m` | No | Write output files |
| step_main_model.m | `MyTool/+mytool/+model/MainModelStep.m` | No | Core calculation logic |
| post_load_checks.m | `MyTool/+mytool/+inputs/PostLoadChecks.m` | No | Validation after loading |
| post_load_manipulations.m | `MyTool/+mytool/+inputs/PostLoadManipulations.m` | No | Transform after loading |
| post_parse_checks.m | `MyTool/+mytool/+inputs/PostParseChecks.m` | No | Validation after parsing |
| post_parse_manipulations.m | `MyTool/+mytool/+inputs/PostParseManipulations.m` | No | Transform after parsing |
| sample.inp | `MyTool/Templates/MyTool_sample.inp` | No | Sample input file |

## Base Templates (Always Generated)

### 1. Main Class (`MyTool.m`)

The main class is the entry point for your tool. It inherits from `ToolBasis` which provides:
- Logging infrastructure
- Input file handling
- Standard execution pattern

**Key Components:**

```matlab
classdef MyTool < ToolBasis

    properties (Constant)
        VERSION = '1.0.0'        % Tool version
        TOOL_NAME = 'MyTool'     % Used by ToolBasis
    end

    properties
        Mdl     % Your main model object
    end
```

**Standard Methods Users Will Call:**

| Method | Purpose |
|--------|---------|
| `MyTool.run(inputFile)` | Run the tool from an input file |
| `MyTool.do_input_checks(inputFile)` | Validate inputs without running |
| `MyTool.copy_inputfiles(targetDir)` | Create sample input file |
| `MyTool.changelog()` | Show version history |

**Execution Flow:**

1. `run()` creates instance and calls `execute()`
2. `execute()` calls `process_inputs()` then `execute_tool()`
3. `process_inputs()` calls:
   - `read_parse_validate_inputfile()` - Load and validate .inp file
   - `do_post_parse_manipulations()` - Transform data
   - `do_post_parse_checks()` - Validate constraints
4. `execute_tool()` runs the SequentialRunner with your steps

**Where to Add Your Code:**

- **Validation logic**: `do_post_parse_checks()`
- **Data transformation**: `do_post_parse_manipulations()`
- **Main execution**: `execute_tool()` (configure Runner and steps)

## Runner Pattern Templates

The **SequentialRunner** pattern breaks execution into discrete steps that pass data via DataKeys.

### 3. DataKeys.m

Constants for passing data between steps. Using constants (not strings) enables tab-completion and catches typos at development time.

```matlab
classdef DataKeys
    properties (Constant)
        Inputs = runner.DataKey('Inputs')
        Results = runner.DataKey('Results')
        % Add more keys as needed
    end
end
```

**Usage in steps:**

```matlab
% Get data
Inputs = Obj.get(mytool.DataKeys.Inputs);

% Set data
Obj.set(mytool.DataKeys.Results, myResults);
```

---

### 4. LoadExternalFilesStep.m

First step in the execution pipeline. Use this to load external files like:
- Input data files (.mat, .xlsx)
- Structural models
- Configuration files

**Key Methods:**

```matlab
function run(Obj)
    Inputs = Obj.get(mytool.DataKeys.Inputs);

    % Load your files here
    data = load(Inputs.dataFilePath);

    % Make data available to later steps
    Obj.set(mytool.DataKeys.MyData, data);
end
```

---

### 5. MainModelStep.m

Core calculation step. This is where your main logic goes.

**Key Methods:**

```matlab
function run(Obj)
    Inputs = Obj.get(mytool.DataKeys.Inputs);
    MyData = Obj.get(mytool.DataKeys.MyData);

    % Your calculation here
    Results = calculate_something(Inputs, MyData);

    Obj.set(mytool.DataKeys.Results, Results);
end
```

---

### 6. WriteFilesStep.m

Final step. Writes results to output files.

**Key Methods:**

```matlab
function run(Obj)
    Inputs = Obj.get(mytool.DataKeys.Inputs);
    Results = Obj.get(mytool.DataKeys.Results);

    % Save to file
    outputPath = fullfile(Inputs.targetDir, 'results.mat');
    save(outputPath, 'Results');

    Obj.Logger.info('Saved results to: %s', outputPath);
end
```

## Input Handling Templates

### 7. get_schema.m

Defines the input validation schema. Each field specifies:
- Default value
- Expected value (for documentation)
- Allowed data types (classes)
- Validation attributes

```matlab
function Schema = get_schema()
    IA = InputAttributes;

    fields = [
        validate.Field('runName', ...
            default = 'default_run', ...
            classes = IA.CLS_CHAR, ...
            attributes = IA.ATTR_CHAR)

        validate.Field('targetDir', ...
            default = '', ...
            classes = IA.CLS_CHAR, ...
            attributes = IA.ATTR_CHAR)

        % Add more fields here
    ];

    Schema = validate.Schema(fields);
end
```

**Common InputAttributes:**

| Attribute | Purpose |
|-----------|---------|
| `IA.CLS_NUM` | Numeric types |
| `IA.CLS_CHAR` | Character/string |
| `IA.CLS_LOGICAL` | Boolean |
| `IA.ATTR_NUM_SCNONNEG` | Non-negative scalar |
| `IA.ATTR_CHAR` | Character validation |

---

### 8. PostLoadChecks.m / PostLoadManipulations.m

Run after loading input files but before parsing.

**PostLoadChecks** - Validate external file contents:
```matlab
function run(Obj)
    % Check that loaded files are compatible
    % Example: Verify file format, check dimensions match
end
```

**PostLoadManipulations** - Transform loaded data:
```matlab
function Inputs = run(Obj)
    % Modify data after loading
    % Example: Convert units, merge data sources
    Inputs = Obj.Inputs;
end
```

---

### 9. PostParseChecks.m / PostParseManipulations.m

Run after parsing and schema validation.

**PostParseChecks** - Validate cross-field constraints:
```matlab
function run(Obj)
    % Check constraints between multiple fields
    % Example: assert(Obj.Inputs.endDate > Obj.Inputs.startDate)
end
```

**PostParseManipulations** - Final data transformations:
```matlab
function Inputs = run(Obj)
    % Compute derived values
    % Example: Obj.Inputs.totalArea = Obj.Inputs.length * Obj.Inputs.width
    Inputs = Obj.Inputs;
end
```

## Sample Input File

### 10. sample.inp

Template .inp file for users. Uses MATLAB syntax:

```matlab
% MyTool Input File
%
% Configuration file for MyTool

runName = "my_analysis"
targetDir = ""

% Add your inputs below
% parameter1 = 100
% parameter2 = "value"
```

**Syntax Rules:**
- Comments start with `%`
- Strings use double quotes `"value"`
- Numbers are plain: `value = 123`
- Booleans: `flag = true` or `flag = false`

## Tips for Tool Developers

### Starting Simple
1. Generate only base templates (MyTool.m + Contents.m)
2. Test basic execution: `MyTool.run(inputFile)`
3. Add steps and DataKeys as needed

### Adding a New Input
1. Add field to `get_schema.m`
2. Add to sample.inp
3. Use in your code via `Obj.Inputs.fieldName`

### Adding a New Step
1. Create step class extending `runner.BaseStep & logging.Loggable`
2. Add DataKey if passing data to other steps
3. Add step to Runner in `execute_tool()`

### Debugging
- Use `Obj.Logger.info('message')` for logging
- Run `MyTool.do_input_checks(file)` to test validation
- Check `Inputs` struct after parsing

## Inherited from ToolBasis

Your tool automatically gets:
- `Obj.Logger` - Logging infrastructure
- `Obj.Inputs` - Parsed input struct
- `Obj.Inp` - Raw InputFile object
- `Obj.info()`, `Obj.warning()`, `Obj.error()` - Logging shortcuts
- `Obj.create_target_dir()` - Create output directory
- `Obj.move_log_file()` - Move log to target dir
